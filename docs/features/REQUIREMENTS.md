# 最小要件定義書（v0.1 MVP）

## 1. 目的とスコープ

- **目的:** ブラウザ側に状態の正本と決定論的な計算ロジックを持たせ、外部PCの画面操作（制御状態）に応じてデータ送信を動的に制御できる、UI非依存のTypeScript同期基盤の最小核を構築する。
- **提供形態:** Gitサブモジュールとして親プロジェクトへ組み込み可能な構成とする。コアパッケージは外部ランタイムおよびUIフレームワークに依存しない（Zero-Dependency Core）。

## 2. アーキテクチャ境界

- **パッケージ分離:** 親プロジェクトから参照される `core`（純粋TS基盤）と、単体検証用の `relay`（最小外部サーバー）および `demo`（2画面動作確認用）をディレクトリ単位で物理分離する。
- **ポート抽象化:** 永続化（`StoragePort`）と通信（`TransportPort`）をインターフェースで分離し、コアロジックからブラウザAPIや通信プロトコルの実装詳細を隠蔽する。
- **実行環境非依存:** コアはDOMに依存せず、メインスレッドとWeb Workerのどちらでも動作する純粋なTypeScriptモジュールとして実装する。v0.1ではメインスレッド動作を標準とし、Worker隔離は課題として後続対応する。

## 3. 機能要件（MVP最小構成）

### 3.1 決定論的ドメインストア（Domain Store）

- JSONシリアライズ可能な構造化ドキュメントを対象とし、状態遷移を純粋関数（Reducer）と追記型イベントログで管理する。
- 初期ストレージアダプターとして **IndexedDB** を提供する。

### 3.2 制御ストア（Control Store）と排他ロック

- 外部PCの画面操作に由来する制御状態（送信対象フィルタ、現在の操作権限者）を、ドメイン状態と分離して管理する。
- 制御状態の変更ごとに単調増加する `controlSeq` を発行する。
- 競合制御の初期仕様は、TTL（有効期限）とハートビートによる単一排他ロック（Exclusive Lease Lock）に固定する。

### 3.3 動的送信エンジン（Reactive Outbox）

- ローカルの未送信イベントと `Control Store` の最新状態を突き合わせ、条件に合致するデータだけを外部へ送信する。
- 送信パケットには適用時点の `controlSeq` を付与する。古い制御状態に基づく送信を、サーバー側で拒否できる契約とする。

### 3.4 Control-First Sync（最小同期プロトコル）

- 接続・再接続時は、必ず `Control Store` の最新状態をサーバーからPullして確定させた後に、`Reactive Outbox` の評価とPushを行う。
- 外部サーバーは、次の機能だけを持つ薄いリレーとする。
  - 部屋（Room）単位の分離
  - `controlSeq` の検証
  - イベントの順序付け
  - SSE等による更新通知

### 3.5 オフライン時のコマンド挙動（Fail-Fast）

- 外部PCからの操作・要求時に対象端末がオフライン（未接続）の場合、サーバーは即座に `TARGET_OFFLINE` エラーを返す。

## 4. 非機能・制約要件

- **型安全性:** TypeScript `strict: true` を満たす。境界でやり取りするイベントと制御メッセージの型契約を明確に定義する。
- **Web単体制約:** ブラウザタブを閉じている間のバックグラウンド処理と常駐応答はスコープ外とする。
- **スキーマバージョン検出:** イベントと制御メッセージに `schemaVersion` を必須で付与する。v0.1では不一致時に安全にエラー停止し、互換性の破壊を検知する。

## 5. スコープ外（後続課題）

v0.1の対象外とする項目は、GitHub Issues（#01〜#10）で管理する。
