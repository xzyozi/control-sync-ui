# ADR-007: controlSeq発行元とストレージアダプターのパッケージ分離

> 現在の仕様の正本は [最小要件定義書](../features/REQUIREMENTS.md) と、今後作成する基本設計書（BD）、IF/API仕様書である。本書は判断理由の記録である。

## 1. 背景・課題

基本設計書（BD）とIF/API仕様書の境界を決めるため、要件定義書の未決事項 OP-01 と OP-04 を確定する必要があった。

- **背景**: `controlSeq` を発行する場所と、ブラウザAPIに依存する IndexedDB アダプターを置くパッケージが決まっていなかった。
- **要求・制約**: FR-03（古い `controlSeq` の送信をサーバーが拒否する）、FR-04（`relay` がイベントを順序付けする）、CN-02（ポート分離）、Zero-Dependency Core。
- **判断しない場合の影響**: BD の責務境界とIFの契約を決められず、設計が止まる。

## 2. 決定

1. **`relay` が `controlSeq` を発行する。** Control Store（ブラウザ側）は、`relay` から受け取った最新値を保持する。
2. **`core` はポートのインターフェースだけを持つ。** IndexedDB アダプターは別パッケージ `storage-indexeddb` とする。

## 3. 理由・代替案

### 採用理由

1. `controlSeq` は、複数の端末や外部PCが同じ制御状態を参照するときの順序の基準である。FR-04 のイベント順序付けと同じ場所（`relay`）で採番すると、サーバー側の拒否判定（FR-03）が1か所で完結する。
2. `core` に IndexedDB の実装を含めると、ブラウザAPIへの依存が入り、Zero-Dependency Core と CN-02 に反する。別パッケージにすると、`core` を Node などブラウザ以外の環境でも検証できる。

### 代替案

| 代替案                                         | 利点                                         | 欠点・リスク                                                                 | 採用しなかった理由                                                 |
| :--------------------------------------------- | :------------------------------------------- | :--------------------------------------------------------------------------- | :----------------------------------------------------------------- |
| クライアント（Control Store）が `controlSeq` を発行する | オフラインでも制御状態を変更できる           | 複数端末で採番が衝突し、単調増加を保証できない。サーバーでの拒否判定が成り立たない。 | FR-02、FR-03 の受け入れ条件を満たせない。                          |
| IndexedDB アダプターを `core` に含める         | パッケージ数が少なく、導入が簡単             | `core` がブラウザAPIに依存する。Node での単体検証がしにくい。                | Zero-Dependency Core と CN-02 に反する。                           |

## 4. 影響・トレードオフ

- **利点**: 順序と拒否判定が `relay` に集まる。`core` を環境非依存のまま保てる。
- **欠点・コスト**: 制御状態の変更には `relay` との通信が必要で、オフライン時は `controlSeq` を進められない。パッケージが1つ増え、親プロジェクトは `storage-indexeddb` を別に組み込む。
- **影響を受ける正本文書**: 要件定義書（FR-02、FR-04、CN-01、CN-02、FR-01）、BD（制御フロー、パッケージ構成）、IF/API仕様書（`controlSeq` の発行と検証のメッセージ）。
- **移行・ロールバック**: 実装前のため、移行は不要。
- **セキュリティ・運用上の影響**: `relay` が `controlSeq` の発行元になるため、認可とテナント分離は [#8](https://github.com/xzyozi/control-sync-ui/issues/8) で扱う。
